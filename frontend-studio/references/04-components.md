# Components follow information relationships

Start from what the section must help a reader understand or do. Reuse project components and keep one page-wide visual language. Recipes below are optional content structures, not a mandatory sequence.

| Section | Useful structure | Common failure to investigate |
|---|---|---|
| Hero | Specific claim, short explanation, primary action, meaningful asset | Many competing focal points or an oversized slogan without evidence |
| Navigation | Identity, relevant destinations, clear current state | Tiny labels, unnecessary controls, hidden keyboard paths |
| Capabilities | Claim tied to a real demonstration | Feature-card wall with repetitive labels |
| Work/case study | Context, selected result, meaningful detail | Fake outcomes or cards nested for decoration |
| Process | Ordered steps with visible relationships | Decorative timeline that obscures the actual method |
| Comparison | Stable criteria, clear differences, honest terms | Motion that prevents simultaneous comparison |
| Pricing | Real price/terms, relevant options, clear action | Invented badges, hidden conditions, excessive visual pressure |
| Form | Labels, sensible grouping, validation, progress/error state | Placeholder-only labels or inaccessible feedback |
| Footer | Relevant secondary navigation and real contact/legal links | A second oversized hero without purpose |

Use cards when content genuinely needs independent grouping. Use spacing and alignment when a container adds nothing. Keep shared title/description/action relationships consistent. Read long and short actual content before deciding widths.

For important creative sections, use 17–18. Mechanism entrances include synchronized product states, in-place case expansion and reflow, SVG-linked steps, interruptible comparison switches, mask-led brand composition, and pointer/drag exploration with equivalent click/keyboard access. Choose according to content; do not reuse the same effect for every theme.

Prototype one section and check initial/middle/end, reading, interruption, focus, reduced motion, and failure before extending it. For external code use 16; adapt structure, content, typography, interaction, and rhythm. Keep the existing framework and do not migrate to suit a library.
