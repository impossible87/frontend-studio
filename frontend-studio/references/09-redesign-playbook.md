# Redesign without losing the site

Read 11 first. Record routes, sections, real copy/data, components, state, forms, assets, framework, fonts, and working behavior. Capture before images with the same viewport/copy planned for comparison.

Diagnose hierarchy, consistency, accessibility, layout, performance, motion, and conversion flow. Findings need file/line or selector, impact, fix, severity, and an observable pass criterion. Preserve real product facts, names, prices, contacts, user records, and navigation unless explicitly authorized to change them.

Select an authorized scope: visual polish retaining structure; medium changes to grouping/components; full redesign preserving facts. Whole-page or creative work uses 17–18, while isolated repairs skip proactive research. Save `design-plans/` with current state→target→specific action→files/behavior affected. Existing authorization is enough to proceed inside scope; ask only for new material business/structural tradeoffs.

Create a reversible working copy or authorized branch; do not create commits without permission. Implement coherent groups, starting with reading order, spacing, and alignment. Prototype one creative mechanism before sharing it across sections. Adapt component structure and interaction beyond recoloring. Keep the framework.

After each meaningful group, run the relevant page, capture/inspect it, and test affected routes, forms, saved state, keyboard, loading, and errors. Compare final before/after at agreed widths with the same content. Check regressions using project tests/build/lint and browser evidence. State unmeasured accessibility/performance areas.

Deliver changes and reasons, runnable instructions, inspected comparisons, source records, test results, remaining risks, and rollback. A screenshot is not proof that production records or forms were preserved; test the relevant behavior.
