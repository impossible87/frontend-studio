# Build and deliver

Choose the smallest stack that fits the actual requirements. Static HTML/CSS/small JS suits a simple showcase. Reusable interactive state can use the project's existing React/Vue/Vite setup. SEO/content/dynamic needs can justify appropriate pre-rendering or an application framework. Do not add a framework to signal professionalism or migrate an existing project for a component.

Keep project conventions. A useful baseline separates tokens, base styles, components, motion, assets, scripts, design decisions, and screenshots; avoid imposing directories an existing app does not need.

Follow the main workflow: brief; reference/creative selection with 17–18; content hierarchy and tokens; typography sample and grayscale skeleton; running representative mechanism; extend sections; concrete copy; purposeful motion; verification; delivery.

Use real shortest/longest content and asset aspect ratios before polishing. Example brands and demonstration data must be labeled. Keep one clear hero focus and stable spacing/alignment in related modules. Do not force a standard hero/features/pricing/testimonial sequence on every brief.

Deliver a runnable artifact and README explaining setup, content/image/font/color editing, dependencies, and a specific deployment option appropriate to the selected stack. Include agreed viewport images, inspection/check results, sources/licenses for imported resources, a placeholder/real-content inventory, and rollback instructions. If it is a reusable template, explain how to replace the brand without breaking hierarchy.

Deployment, public uploads, and irreversible operations require the user's authorization. Finish local implementation and validation before requesting approval for a concrete publication action.
